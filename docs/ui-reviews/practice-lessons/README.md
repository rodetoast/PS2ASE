## 실기동·자동 검증

- Photoshop 2027(28.0.0)에서 실제 CLI 워커로 두 합성 PNG를 검사했습니다. 다른 합성 문서는 복사되지 않았고 metadata/trigger도 생성되지 않았습니다. 올바른 파일은 정확한 RGBA의 14×11 레이어 하나를 추출했습니다. 그 합성 문서만 저장하지 않고 닫았고, 기존 활성 문서와 Photoshop 눈금자 단위가 복원됐습니다.
- Aseprite 1.3.18.6의 격리된 배치 실행에서 복사, 일반 붙여넣기, 연습 붙여넣기와 성공 토큰을 확인했습니다. 실제 이미지와 트랜잭션은 호스트 API이며 클립보드, 알림, 콘솔은 시험 입력으로 제어했습니다. 일반 텍스트/스칼라/다른 시그니처, 누락 metadata·PNG, 손상 PNG, 만료된 연습 및 다른 대상은 문서를 변경하지 않았습니다.
- 자동 테스트 139개가 통과했습니다(건너뜀 0개). 승인 전과 충돌 발생 시 키 파일 보호, 승인 후 백업, 경고의 양방향 변경, 가이드 격리 및 이전 응답 거부, Undo/Redo 연결, 정렬 저장을 확인했습니다. 실행 명령은 `python -B -m unittest discover -s tests -p 'test_*.py'`입니다. 프로젝트 루트를 `PYTHONPATH`로 지정하고 `NODE_BINARY`, `PS2ASE_ASEPRITE_TEST_EXE`를 실제 도구 경로로 지정했습니다.
- 기존 Normal/중앙 기준 실제 양방향 전송과 좌표·알파 비교는 [이전 실기동 보고서](../setup-practical-check/HOST_VALIDATION.md)를 재사용합니다. 완전 투명한 픽셀의 숨은 RGB를 바꾸는 변경은 하지 않았습니다.

## 수동 인계

실제 사용자 프로필에 스크립트/키 파일을 설치하거나 Photoshop 설정을 변경하지 않았습니다. 기존 설치 사용자는 Aseprite를 종료한 뒤 가이드나 환경 설정에서 스크립트 업데이트를 직접 승인합니다. 기존 F4/F5가 다른 동작에 배정됐다면 대상 키가 표시된 동의창을 확인합니다. 백업은 Aseprite 설정 폴더에 남습니다. 업데이트 후 승인창이 나타난다면 개인이 직접 대상 스크립트를 확인하고 선택해야 합니다.

1. 가이드에서 F5 연습 PNG를 열고 그림이 있는 셀을 선택한 뒤 F5를 누릅니다. 일반 복사본과 미리보기가 그대로인지 확인합니다.
2. 결과가 수신되면 F4 연습으로 이동합니다. Photoshop 전용 PNG를 열고 가이드에서 복사한 뒤, 별도 빈 Aseprite 연습 PNG에서 F4를 누릅니다. 그림과 새 결과 표시를 확인하세요. 자동 표시가 안 뜨면 화면을 확인한 경우에만 수동 확인 버튼을 사용합니다.
3. 두 테스트 문서를 저장하지 않고 닫고 점검표를 확인합니다. 앱 세션을 유지한 채 가이드를 다시 열어 결과 표시를 확인합니다.

새 흐름의 물리 F4/F5 및 창 전환, 업데이트 뒤 Trust 재승인 필요 여부는 실제 사용자 GUI에서 별도 확인해야 합니다. 새 후보·정식 EXE와 ZIP을 만들지 않았으며 운영 배포는 변경하지 않았습니다.
