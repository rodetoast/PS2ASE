# 첫 실행 소개와 다중 레이어 실습

[디자인 기준](../../design-references/onboarding-guidance-followup/README.md) · [프로젝트 상태](../../PROJECT_STATUS.md)

- [첫 실행 소개](introduction.png): 기본 복사의 레이어 유지와 레이어 → 프레임의 연속 배치를 비교합니다. PSD 실제 파츠 썸네일, Aseprite 예제, 설정 시작/바로 작업 선택을 사용합니다.
- [Photoshop 연결](connection.png): 감지 결과에서 실행 경고 확인으로 이어지는 네 단계 가이드입니다.
- [F4 문서 열기](f4-open.png) → [다중 레이어 선택](f4-practice.png): 열기 응답 전에는 복사를 잠그고, 연습 탭이 활성화된 상태에서 01~04를 복사합니다. 캡처는 격리 Qt 재현 상태입니다.
- [Aseprite 도움말](script-menu-help.png): 격리 Aseprite 1.3.18.6에서 캡처한 실제 File > Scripts 메뉴입니다. Trust 승인창은 촬영하지 않았고 합성하지도 않았습니다.
- [기본 미리보기](preview-default.png): 같은 Windows Qt 175% 화면, 배너 숨김, 460 논리 픽셀 너비에서 기존 창 높이 690과 새 높이 754를 비교했습니다. 표시 영역은 122 → 186 논리 픽셀(+52%), 더 큰 창에서는 272입니다. 최근접 보간과 종횡비를 유지합니다.

## 실제 호스트 검증

- 신고 로그에는 Photoshop 2027 (28.0.0)에서 문서가 0개인 시도와, 문서가 열렸지만 정확한 실습 탭이 아닌 시도가 각각 있습니다. 같은 환경에서 일반 Normal 복사 성공도 기록됐으므로 형식 자체가 원인이라고 볼 근거는 없습니다. 과거에 열린 탭의 정확한 경로는 로그 마스킹 때문에 확정하지 않았습니다.
- Photoshop 2027의 검증된 EXE CLI로 세션 연습 문서 열기와 일반·연습 Normal 복사를 각각 실행했습니다. PSD는 순서대로 별도 PNG 4개, PNG는 단일 픽셀 레이어를 내보냈습니다. 다른 탭을 대상으로 한 실습 복사는 metadata 없이 거부됐습니다. 열기만 한 작업에는 클립보드 채택 marker가 없습니다.
- 기존 Aseprite 1.3.18.6의 격리 배치에서 이 PSD 결과를 빈 300×300 연습 대상에 붙였습니다. 네 cel의 순서·가시 RGBA·알파와 중앙 좌표 (106,105), 일치하는 완료 nonce를 검증했습니다. 레이어 이름을 강제하는 변경은 하지 않았습니다. 기존 Normal paste의 대상 레이어 재사용 동작을 유지합니다.
- 재현 중 사용자의 Photoshop 문서를 수정·저장하지 않고, 시험 파일만 닫았습니다. 기존 Trust/경고 설정 및 일반 클립보드 변경은 하지 않았습니다.
- 자동 테스트 147개 통과. 원본 문서 없음과 같은 이름의 다른 경로 거부는 모의 JSX 검사도 통과했습니다. 작업 중인 Photoshop을 종료하지 않았으므로 실호스트 콜드 스타트, 물리 F5/F4 재시험, 최초 Trust 승인창, 새 패키지 빌드는 미검증입니다.
