# 기존 사용자 환경의 실기동 검증 (2026-11-25)

기준 소스 [`14391c6`](https://github.com/rodetoast/PS2ASE/commit/14391c684a70ea119ce638860daaee496fcdba0f). Windows 개발 PC에서 Python 소스로 실행했고, 실제 Photoshop 2027(28.0.0)과 Aseprite 1.3.18.6의 활성 합성 문서에 Windows 키 입력을 보냈습니다. 물리 키보드 스위치는 시험하지 않았습니다. 업무 문서를 수정·저장·닫지 않았고, Bridge 설정 파일과 Aseprite 단축키 파일의 SHA-256은 전후 동일했습니다.

## 가이드

- F5로 가이드가 생성한 합성 PNG의 새 결과 1개를 받았습니다. 이전 Photoshop 복사본의 클립보드 내용·변경 번호·반전 PNG 해시가 F5 전후 동일했습니다. 가이드 결과는 일반 클립보드 갱신 전에 별도 처리됩니다. 실행 취소 이력을 클릭하여 전후 스택을 직접 비교하지는 않았습니다.
- 일반 텍스트 상태에서 한 번 실패한 F4는 유효한 Photoshop 테스트 복사본을 다시 넣은 뒤 실제 붙여넣기를 확인했습니다. 완료 화면에서 F5 새 결과와 F4 확인이 구분되어 표시됐으며, 닫았다 다시 열어도 점검표 결과가 같은 앱 세션에서 유지됐습니다.

## 가이드 종료 후 일반 전송

- Photoshop → Aseprite: Normal/중앙 기준. 실제 `.aseprite` 사본은 32×32, 1프레임, 기존 활성 레이어 1개를 재사용했습니다. cel은 (9, 7), 14×17, 불투명도 255이며 원본에서 자른 RGBA와 바이트 단위로 일치했습니다.
- Aseprite → Photoshop: 같은 cel을 실제 F5로 복사하고 Bridge에서 붙여넣었습니다. 32×32 대상에 새 ArtLayer 1개가 기존 레이어 위에 생성됐고, 새 레이어의 경계는 (9, 7)–(23, 24), 기존 레이어는 (7, 5)–(21, 22) 그대로였습니다. 새 레이어 재추출 결과 불투명 150픽셀의 RGB와 전체 알파가 같았습니다. 완전 투명 88픽셀의 숨은 RGB는 달라 전체 RGBA 바이트는 동일하지 않았습니다. 숨은 RGB가 변한 정확한 단계는 분리하지 않았습니다.

## 발견 사항

1. **완료 콘솔이 연속 단축키를 막음.** Aseprite 1.3.18.6에서 합성 문서에 F5를 누르면 복사는 완료되지만 Lua의 `print` 대체 경로가 모달 콘솔을 띄웁니다. 콘솔을 닫지 않고 F4를 누르면 붙여넣기가 실행되지 않습니다. F4 성공 뒤에도 같은 유형의 완료 콘솔을 확인했습니다. 콘솔을 닫으면 다음 입력을 받습니다.
2. **일반 텍스트에 F4를 누르면 Lua 파싱 오류가 노출됨.** 활성 합성 문서에서 완료 콘솔을 닫고, 클립보드가 Bridge JSON이 아닌 일반 텍스트인 상태에서 F4를 누르면 `aseprite_paste.lua:5: expected value, got (-20)`가 표시됐습니다. 이번 입력에서 관측된 코드이며 다른 문자열이면 오류 문구가 달라질 수 있습니다. 원인은 시그니처 검사 전에 보호되지 않은 `json.decode`를 호출하는 순서입니다. 클립보드가 누가 변경했는지는 확인되지 않았으며, 별도로 계측한 가이드 F5 직후 클립보드는 그대로였습니다.

최초 Trust 승인, 다른 호스트 버전, 다른 모드·정렬의 재시험과 패키징은 이번 범위가 아닙니다. 제품 코드, 기존 후보, 운영 0.3.6은 변경하지 않았습니다. 기존 업무 문서가 보이는 원본 화면과 클립보드 내용은 공유 자료에 포함하지 않았습니다.
