# F5 복구, 설치 상태와 픽셀 미리보기 (2026-11-26)

Windows PySide6 자동 렌더링입니다. [온보딩 디자인 시안](../../design-references/onboarding-redesign/README.md)의 타임라인을 재사용하고, 설명보다 연습 파일을 여는 행동을 먼저 배치했습니다. 사용자의 업무 문서·승인창·개인 설정은 캡처하지 않았습니다.

## 원인 조사

개발 PC의 Aseprite 1.3.18.6, 실제 등록된 F5 경로 및 설치본을 읽기 전용으로 확인했습니다. F5는 해당 사용자 Aseprite 스크립트 폴더의 `aseprite_copy.lua`에 매핑되어 있었으며, 설치본 SHA-256과 개발 소스 `0c35a17`의 파일이 일치했습니다. 실제 Bridge 설정 파일은 읽을 수 있었고 `active_temp_path`의 디렉터리도 존재했습니다. 조사 시점에는 신고 당시 Bridge와 연습 파일이 남아 있지 않았으므로, 당시 활성 경로, 실제 실행 파일의 순간 상태와 `app.fs.isFile` 결과는 복구하지 못했습니다.

동일 버전 Aseprite의 격리 시험에서 구 Lua를 사용했고, 올바른 설정을 둔 상태로 연습 파일을 연 뒤 **디스크의 시험용 복사본만 제거**했습니다. 실제 `app.fs.isFile`이 false가 되며 동일한 한국어 “먼저 Bridge를 열어 주세요” 오류를 재현했습니다. 이 조건에서 구 문구가 잘못됐음은 확인했지만, 과거 신고의 정확한 분기를 확정한 것은 아닙니다.

새 코드는 가이드가 생성한 세션 토큰과 정규화된 활성 문서 경로를 검증한 후 실제 파일을 확인합니다. 네이티브 파일 확인이 실패하면 **같은 검증된 경로에서 읽기 전용으로 열리는지** 확인합니다. 세션·파일·접근·설정·출력 실패는 별도 안내로 종료되며 일반 클립보드로 우회하지 않습니다. 실패 시 기술 상세는 가능할 때 로컬 로그 `aseprite_copy_diagnostic.json`에 남기고, Bridge 진단 콘솔에는 개인정보 없는 요약만 기록합니다. 폴더가 사라졌거나 접근이 막혀 로컬 로그도 기록할 수 없는 경우에는 사용자 안내는 그대로 표시됩니다.

## 검증 범위

자동 테스트 144개 통과(건너뜀 0개), `git diff --check` 통과.

- 설치가 필요하면 실행 중에는 저장 후 종료 안내를, 확인 불가에는 별도의 상태 다시 확인 안내를 표시합니다. 종료 확인으로 버튼이 활성화돼도 자동 설치하지 않습니다. 실행 도움말은 연습 파일이 생긴 뒤에만 보여 주고, 메뉴에서 직접 실행하는 방법과 파일 접근 승인 안내를 구분합니다. 점검표는 스크립트의 수신 결과와 과거 권한 확인 기록을 혼동하지 않습니다.
- 실제 설치된 Aseprite 엔진을 격리 프로필에서 자동 실행해 정상 복사, 다른 세션, 실제 파일 누락, stat 실패 후 읽기 성공, 읽기 접근 거부, Bridge 설정 없이 가이드 복사, 빈 프레임을 검사했습니다. 실제 Lua 결과를 새 Qt 가이드가 받고 F4 연습 파일을 준비하는 것까지 확인했습니다. Photoshop에는 명령을 보내지 않았습니다.
- 미리보기 워커는 합성 픽셀의 원본 크기를 유지합니다(큰 결과만 최대 1536픽셀로 최근접 축소). **47×43 픽셀** 예시는 기본 창에서 **140×128**, 확대 창에서 **304×278** 논리 픽셀입니다. 100%·200% Qt 배율에서 비교했고, 좁은 창 접근성과 극단적인 가로·세로 비율, 큰 이미지, 투명도 및 최근접 색상 보존을 자동 검사했습니다. 원본 PNG와 편집·Undo/Redo·전송에는 영향을 주지 않습니다.
- 사용자가 자동 검증만 선택했으므로 실사용 프로필에 업데이트를 설치하거나 실제 F5 키를 보내지 않았습니다. 후속 수동 검증은 새 소스 실행, Aseprite 저장 후 종료, 스크립트 업데이트 직접 승인, 새 연습 탭의 Layer 1 / 프레임 1에서 F5입니다. 운영 0.3.6, 기존 0.3.7-rc1, 사용자 데이터 및 설치본은 그대로이며 새 배포 파일을 만들지 않았습니다.
