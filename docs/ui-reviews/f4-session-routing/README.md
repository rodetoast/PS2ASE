# F4 실습 세션과 일반 붙여넣기 분리

## 재현 및 원인

- 사용자 환경의 F4는 설치된 `aseprite_paste.lua`를 가리켰고, 당시 설치본과 6a40d3e 원본의 SHA-256이 일치했습니다. Photoshop 로그에는 Normal 모드, 픽셀 레이어 4개와 PNG 4개가 기록돼 있었습니다.
- Windows의 실제 TEMP 환경 변수는 8.3 짧은 경로를 사용했고, Aseprite 최근 문서에는 같은 실습 PNG가 긴 경로로 기록돼 있었습니다. 마감된 원래 세션의 JSON은 남아 있지 않았습니다. 동일 파일에 대해 JSON에는 짧은 경로를 쓰고 GUI에서는 긴 경로로 열어 [이전 F4 오류를 재현](legacy-f4-rejection.png)했습니다. 캔버스는 300×300이고 만료 전, 4레이어 Normal 작업이었습니다.
- 기존 경로 비교는 슬래시와 대소문자만 정규화했습니다. 이제 Bridge가 디스크의 긴 경로를 얻어 실습 루트를 생성하고, Lua에서 정확한 대상 경로·세션·nonce·만료·작업 폴더·캔버스·첫 프레임·레이어 수·프레임 모드를 확인합니다. 실행 좌표와 레이어 처리 자체는 기존 붙여넣기 로직을 사용합니다.

## 실제 Windows GUI 확인

| 시나리오 | 결과 |
| --- | --- |
| 유효한 실습 탭, 키보드 F4 입력 | Aseprite 1.3.18.6에서 검은 캐릭터가 표시됐고 4개 레이어 처리 및 `shortcut` 수신을 확인했습니다. |
| [가이드 전용 버튼](button-complete.png) | 실제 Qt 버튼을 클릭해 설치 스크립트를 실행했습니다. `button`으로 수신하고 F4 키는 미확인으로 남겼습니다. |
| 가이드 단계 종료 후 남은 실습 탭 | 실제 F4에서 세션 종료 안내와 `sidecar_missing` 진단이 기록됐습니다. 일반 데이터로 전환하지 않았습니다. |
| 별도 [일반 탭](ordinary-gui-canvas.png) | 실제 Aseprite GUI에서 F4를 누르고 시험 문자열만 주입해 제품 Lua의 일반 분기를 실행했습니다. 첫 프레임에 4개의 비어 있지 않은 cel과 (106,105) 좌표를 확인했습니다. 시스템 클립보드는 바꾸지 않았습니다. |
| 닫힌/실행 중 호스트의 열기 | 설치된 EXE가 정규화된 합성 문서를 열어 GUI에 표시하는 것을 확인했습니다. 자동 테스트에서 닫힘은 직접 열기, 실행 중/확인 불가는 정확한 탐색기 파일로 안내하며 중복 실행하지 않음을 확인했습니다. |

일반 탭에 실습 sidecar가 영향을 주지 않는 경우, 만료, 다른 경로, 세션 불일치, 다른 문서에 대한 버튼 요청, 캔버스와 레이어 수 오류, 접근 거부, 옮겨진 동일 이름의 실습 탭은 배치 회귀에 포함했습니다. 기존 정상 변환 코드와 일반 Bridge 클립보드·미리보기·Undo/Redo를 바꾸지 않았습니다.

## 구현 화면과 배포 범위

- [PSD 붙여넣기 준비 화면](f4-ready.png): 실제 PSD 파츠 합성 이미지와 01~04 레이어, 문서 열기/붙여넣기 행동을 보여 줍니다.
- [도움말](script-menu-help.png) · [좁은 창](script-menu-help-narrow.png): Aseprite UI 배율을 높여 실제 메뉴를 700×525로 다시 찍었습니다. 실제 읽기 승인창을 경로만 가려 함께 넣었습니다. Windows Qt 175%에서 좁은 320 논리 픽셀 창을 확인했습니다.
- 사용자 Trust는 수정하지 않았습니다. 승인받은 격리 프로필에서만 읽기/쓰기를 승인했습니다. 사용자 설치본은 업데이트하지 않았습니다. 사용자 프로필의 시스템 클립보드와 메인 창 일반 붙여넣기 전체 연쇄는 미검증입니다.
- 자동 테스트 148개 통과. 운영 0.3.6 및 기존 0.3.7-rc1 유지. 새 EXE, ZIP, 운영 게시 없음.
